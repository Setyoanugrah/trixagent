02 / System surface

One control plane.
Six working layers.

TrixAgent combines remote direction, bounded execution, browser control, multimodal inspection, and durable state in a runner designed to survive handoffs.

01

Telegram control

Owner-gated commands, durable task intake, inline approvals, and task updates delivered where the work begins.

control.telegram
02

Code + shell

Confined workspace reads and edits, command execution, builds, and tests with bounded output and secret-free subprocesses.

runtime.exec
03

Chromium / CDP

Persistent browser context, navigation, page snapshots, screenshots, and targeted interaction through a controlled Chromium session.

browser.cdp
04

Vision

Gemini Flash inspects screenshots and inbound images when visual state carries information text alone cannot recover.

vision.inspect
05

Durable Nebula memory

Messages, tasks, checkpoints, approvals, tool runs, and browser state persist beyond any single ephemeral runner.

memory.nebula
06

Automatic handoff

A renewable lease selects one active runner while a standby can acquire the workload after expiry and resume from checkpoints.

runner.handoff

03 / Control channel

This page watches.
Telegram directs.

Open the bot to create work, inspect state, resume checkpoints, or cancel an active task. The public dashboard cannot issue commands.

Open @trixtom_bot ↗
telegram://trixtom_bot EXACT COMMANDS
  1. /startShow the command surface.
  2. /statusRead runner, model, lease, browser, and task state.
  3. /newReset conversation context and cancel open work.
  4. /resumeContinue the latest resumable task from its checkpoint.
  5. /cancelCancel the current task and pending approvals.
  6. /browserReturn the current browser snapshot.
  7. /screenshotCapture the current browser page.
  8. /memory deploymentSearch durable memory for “deployment”.
› Plain text, photos, and documents create durable tasks.
